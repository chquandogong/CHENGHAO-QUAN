Prism · 개인 지식 시스템

AI와 나눈 판단이
흩어지지 않게.

여러 AI 어시스턴트를 오가며 내린 결정과, 그때 버린 대안을 한곳에 모아 다음 작업 앞에 다시 꺼내 놓는 시스템입니다. 어시스턴트는 셋인데, 그 사이에 공유된 기억은 없었습니다.

자동화는 흔적을 목록화한다. 무엇이 지식이 될지는 사람이 정한다.

Prism이 한 사람의 판단이 흩어지지 않게 한다면, Knowledge Hub는 조직과 조직 사이의 답이 흩어지지 않게 합니다.

처음 풀려던 문제

월요일에 Claude Code에서 내린 결정을, 목요일의 Codex는 들어본 적이 없습니다.

대화와 작업이 다섯 개의 축에 흩어집니다 — 제공자(Claude·OpenAI·Gemini) × 요금제(회사·개인) × 화면(웹·데스크톱·CLI) × 머신 × 작업 폴더. 각 서비스의 검색과 메모리는 자기 경계 안에서만 동작하고, 서로 호환되지 않습니다. 근거는 디스크의 로그 파일에 그대로 있지만, 그걸 다시 읽는 것은 아무것도 없습니다.

손실 1

재작업

"이거 전에 했었나?" — 못 찾아서 다시 합니다.

손실 2

버린 쪽의 소실

"그때 왜 그쪽을 안 골랐지?" — 선택은 코드에 남지만 버린 대안은 어디에도 없습니다.

손실 3

변화 대응 지연

새 모델·제품이 나와도 우리 일과 관련 있는지 바로 판단할 체계가 없습니다.

컨셉 — 토대 하나, 기둥 넷, 지붕 하나

이름은 빛을 받아 스펙트럼으로 나누는 프리즘에서 왔습니다. 쏟아지는 변화를 우리 관점으로 분해해, 의미 있는 것만 남긴다는 뜻입니다.

지붕 — 전달폰에서 읽히는 홈 노트 · 트렌드 다이제스트 · 클라우드 어시스턴트용 읽기 전용 창구
기둥 1위키마크다운 파일이 정본. 한국어 대응 하이브리드 검색(어휘 + 의미)
기둥 2도메인 렌즈외부 소스의 변화를 회사 관심사 프로파일로 0–5점 채점
기둥 3루프세션을 증류해 결정·버린 대안·노하우를 남김. 쓰기 전에 반드시 묻는다
기둥 4회상 우선새 세션을 시작하면 이미 적어둔 것을 먼저 앞에 놓는다
토대 — 수집Claude Code·Codex 세션 로그와 내 git 커밋을 매일 밤 목록화하고 원본을 보관

목록화는 빠짐없이

세션 로그를 읽는 비용은 거의 없고, "어디서 무엇을 했는지"는 틀릴 일이 없습니다. 그래서 수집은 전부 자동입니다.

지식은 작게

남길 가치가 있다는 건 판단이고, 기계가 내린 판단은 여섯 달 뒤 아무도 믿지 않습니다. 위키에 쓰는 건 사람이 시킬 때만입니다.

닫힌 쪽이 기본

밖에서 닿는 창구로는 회사 노트가 나가지 않습니다. 분류가 빠진 노트도 회사 노트로 취급합니다. 기기 동기화·백업·AI 어시스턴트에게 건네는 노트는 이 게이트 밖의 경로라 따로 다룹니다.

왜 직접 만들었나

부품은 이미 성숙했지만, 이 조합을 통째로 해결하는 제품은 찾지 못했습니다.

이미 있는 것빠진 것
브라우저 확장 — 웹 대화 검색CLI·데스크톱 작업은 못 봄
세션 인덱서 — CLI 로그 검색"어느 요금제·머신·폴더였나"의 출처 추적, 지식으로의 승격이 없음
메모리 레이어 — 추출된 사실 저장버린 대안과 이유는 남지 않음. 자동 추출이라 판단을 믿기 어려움
화면 상시 기록회사 자료까지 전부 기록돼 프라이버시 부담이 큼

그래서 처음부터 다 만들지 않고, 기존 부품(Obsidian vault, SQLite, 로컬 임베딩 모델, MCP) 위에 얇은 통합 계층을 얹었습니다. 임베딩은 이 컴퓨터에서 돌립니다 — 노트마다 외부 API를 부르는 건 노트마다 무엇을 밖으로 내보낼지 정하는 일이기 때문입니다.

정말 필요하고, 가치가 있나

만든 것과 쓰이는 것은 다른 일입니다. 그래서 위키를 꺼내 쓸 때마다 기록을 남기게 해 두었습니다. 지난 30일(2026-09-03 ~ 10-02)의 기록입니다.

199회상 시도 · 이 중 24번(AI의 위키 검색)은 오류로 끝나 아무것도 돌려주지 못함
14/30일사람이나 AI가 직접 검색한 날
24%세션 시작 훅이 이 프로젝트의 노트를 찾아 내민 비율 (29회 중 7)
0/24AI가 위키를 검색해 답을 받은 횟수 — 8/28부터 있던 결함으로 전부 오류였고 10/2에 고침

확인됨 문제는 진짜다

  • 세션은 실제로 흩어지고, 도구는 원본 로그를 지우거나 잘라냅니다(Claude Code는 오래된 기록을 주기적으로 삭제). 따로 보관하지 않으면 근거가 사라집니다.
  • "그때 왜 안 골랐지?"에 답하는 기록 — 버린 대안 — 은 다른 어떤 도구에도 남지 않습니다.
  • 외부 창구가 회사 노트를 내보내지 않는다는 규칙에는 규칙마다 테스트가 붙어 있습니다.

미확인 들인 만큼 돌려받는가

  • AI가 위키를 찾는 통로(로컬 MCP 검색)는 한 달 동안 결과마다 오류였는데, 회상 기록에는 성공으로 남아 아무도 몰랐습니다(10/2 수정). AI의 세션 검색은 27번 중 10번 결과가 나왔습니다.
  • 35일간 코드 1.9만 줄을 만들었지만, 하루 평균 회상은 7회 안팎이고 그중 일부는 개발 중의 시험 검색입니다(추정).
  • 세션 시작 훅이 이 프로젝트에서 적어둔 노트를 찾은 것은 넷 중 하나이고, 찾아 내민 것도 지금 작업과 무관한 경우가 있습니다.
  • 원래 계획은 "회상 기능만 먼저 2–4주 써서 가치를 확인한 뒤 확장"이었는데, 렌즈와 원격 창구가 같은 날 함께 들어갔습니다. 검증 관문을 건너뛴 셈입니다.

지금의 결론: 문제는 실재하고 토대는 쓸 만하지만, 이 시스템이 들인 시간만큼 재작업을 줄였다는 증거는 아직 없습니다. 판단에 쓰던 기록마저 부풀려져 있었습니다 — 기록된 AI의 위키 검색 24번은 하나도 답을 돌려주지 못했습니다. 기능을 더 얹기보다, 이미 있는 것을 쓰면서 재는 단계입니다.
